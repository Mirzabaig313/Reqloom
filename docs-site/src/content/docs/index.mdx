<p class="eyebrow">The problem</p>

## Six requests before the one you care about

Modern SaaS backends are multi-actor. To exercise *admin approves a customer
refund*, you first authenticate as three different actors and create half a
dozen prerequisite records — then copy IDs and bearer tokens between tabs
until the request you actually wanted to test finally returns a 200.

Reqloom treats the API as what it already is: a directed graph of resources,
actors, and dependencies. You describe that graph once, in a file you can
review in a pull request. After that, one command runs any node in it.

```bash title="Terminal"
reqloom run refund.approve --project marketplace
```

```ansi title="Resolved chain"
vendor.login          201  142ms
customer.verify_otp   200   88ms
product.create        201  113ms
product.publish       200   79ms
order.create          201  164ms
order.pay             200  402ms
refund.request        201   97ms
refund.approve        200  121ms

8 steps · 1.2s · 0 manual copy-paste
```

<p class="eyebrow">How it works</p>

## Four ideas, and that's the whole model

<Steps>

1.  **Actors** own credentials. `admin`, `vendor`, `customer` — each with its
    own auth flow, defined once. [Actors →](/concepts/actors/)

2.  **Resources** group operations. A resource declares what it needs to
    exist before it can be used. [Resources →](/concepts/resources/)

3.  **Dependencies** are declared, not scripted. Reqloom topologically sorts
    them and executes in order. [Resolution →](/concepts/dependencies/)

4.  **Variables** carry values forward. Extract an ID from step 2, reference
    it in step 6. [Variables →](/concepts/variables/)

</Steps>

## Built for the parts that usually hurt

<CardGrid>
    <Card title="Chains resolved for you" icon="rocket">
        Pick an endpoint. The engine walks your schema, builds the
        prerequisite chain, and runs it in topological order — reusing
        anything already satisfied.
    </Card>
    <Card title="Multi-actor by default" icon="padlock">
        Each actor's login, token refresh, and OTP flow lives in the schema.
        Sessions are cached, so you don't re-authenticate every morning.
    </Card>
    <Card title="One schema, every environment" icon="setting">
        Local, staging, production. Same file, different `--env`. Secrets stay
        in your OS keychain, not in the schema.
    </Card>
    <Card title="Reviewable in a pull request" icon="code-branch">
        Plain YAML. Diffs are readable, conflicts are resolvable, and the
        schema lives next to the code it tests.
    </Card>
    <Card title="Importer for what you already have" icon="puzzle">
        Turn an OpenAPI spec, a Postman collection, or a pasted curl log into
        a runnable schema instead of retyping it.
    </Card>
    <Card title="Local-first, Apache 2.0" icon="approve-check">
        The engine, CLI, schema, and desktop app are open source. Your
        projects and run history stay on your machine.
    </Card>
</CardGrid>

## Where it sits next to the tools you know

Postman, Bruno, and Insomnia are HTTP clients: excellent at composing and
sending a single request. Reqloom is a workflow engine that happens to speak
HTTP — the value is in what it does *between* requests.

|                                | Postman | Bruno | Insomnia | Reqloom |
| ------------------------------ | ------- | ----- | -------- | ------- |
| Send a single request well     | <span class="yes">yes</span> | <span class="yes">yes</span> | <span class="yes">yes</span> | <span class="yes">yes</span> |
| Auto-resolved request chains   | <span class="no">no</span> | <span class="no">no</span> | <span class="no">no</span> | <span class="yes">yes</span> |
| First-class actor abstraction  | <span class="no">no</span> | <span class="no">no</span> | <span class="no">no</span> | <span class="yes">yes</span> |
| Importer for arbitrary specs   | <span class="partial">partial</span> | <span class="no">no</span> | <span class="partial">partial</span> | <span class="yes">yes</span> |
| Git-friendly schema files      | <span class="partial">partial</span> | <span class="yes">yes</span> | <span class="partial">partial</span> | <span class="yes">yes</span> |
| Open source                    | <span class="no">no</span> | <span class="yes">yes</span> | <span class="partial">partial</span> | <span class="yes">yes</span> |
| Local-first by default         | <span class="no">no</span> | <span class="yes">yes</span> | <span class="no">no</span> | <span class="yes">yes</span> |
| CLI built for CI               | <span class="partial">partial</span> | <span class="yes">yes</span> | <span class="partial">partial</span> | <span class="yes">yes</span> |

If your workflow is *one request at a time*, an HTTP client is the right
tool and Reqloom is overhead. The trade pays off once a request has
prerequisites.

## Getting it running

<Aside type="caution" title="Pre-1.0">
Reqloom has not cut its first release yet, so the package managers below are
not live. **Building from source is the supported path today** — see
[Building from source](/dev/building/). The other tabs document where the
binaries will land at v1.
</Aside>

<Tabs>
    <TabItem label="Build from source">
        ```bash
        git clone https://github.com/Mirzabaig313/Reqloom
        cd Reqloom
        cmake --preset macos-debug      # or linux-debug / windows-debug
        cmake --build --preset macos-debug
        ./build/macos-debug/cli/reqloom --help
        ```
        Needs CMake 4.0+, a C++23 compiler, and Qt 6.8 LTS. Full
        prerequisites: [Building from source](/dev/building/).
    </TabItem>
    <TabItem label="macOS">
        ```bash
        # Planned for v1 — not yet published.
        brew install reqloom/tap/reqloom
        ```
    </TabItem>
    <TabItem label="Linux">
        ```bash
        # Planned for v1 — not yet published.
        curl -fsSL https://github.com/Mirzabaig313/Reqloom/releases/latest/download/reqloom-linux-x86_64.AppImage -o reqloom
        chmod +x reqloom
        ```
    </TabItem>
    <TabItem label="Windows">
        ```powershell
        # Planned for v1 — not yet published.
        scoop bucket add reqloom https://github.com/Mirzabaig313/scoop-reqloom
        scoop install reqloom
        ```
    </TabItem>
</Tabs>
